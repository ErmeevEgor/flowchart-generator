# Режимы генерации

## `process_only`

Создаёт одну схему всего процесса. Это режим по умолчанию, если пользователь не выбрал другой вариант.

Выходные файлы:

```text
<name>.json
<name>.drawio
<name>.svg
```

Используй его, когда:

- пользователь просит одну схему;
- процесс умещается в одной читаемой схеме;
- источник не содержит обоснованных границ подпроцессов;
- уровень детализации не указан.

## `process_with_subprocesses`

Создаёт обзорную схему и отдельные схемы подпроцессов.

Выходная структура:

```text
<name>/
  manifest.json
  overview/
    overview.json
    overview.drawio
    overview.svg
  subprocesses/
    <subprocess-id>.json
    <subprocess-id>.drawio
    <subprocess-id>.svg
```

Используй его только по прямому запросу пользователя. Подпроцесс допустим, когда источник сам показывает устойчивую смысловую границу, например:

- отдельный названный процесс или процедура;
- действие верхнего уровня раскрыто последовательностью внутренних шагов;
- раздел инструкции имеет собственные начало, результат и связанный набор действий;
- источник явно ссылается на подпроцесс.

Не считай подпроцессом произвольную группу соседних шагов, роль, систему, документ или ветку решения. Не дели процесс только из-за числа узлов.

Обзор должен оставаться понятным без открытия деталей. Поле `overviewNodeId` связывает каждую детальную схему с конкретным узлом обзора; runtime автоматически добавляет этому узлу пометку `Подпроцесс: <название>`. Если ни одна граница не подтверждается источником, создай `process_only` и сообщи, что безопасная декомпозиция невозможна без дополнительных данных.
